# Juno Docs Agent Rules

These rules apply to any assistant editing `docs-site/`.

1. Build the docs directly. Do not prepare instructions for another agent unless Jas asks.
2. The public product name is Juno.
3. Write for final public launch docs, not an early dogfood release.
4. Do not write final prose unless working on an approved page batch.
5. Do not invent install commands, API schemas, screenshots, diagrams, or launch claims.
6. Do not claim production readiness, signing, notarization, secure-field behavior, or local-only behavior unless verified.
7. User docs must avoid internal repo/package terminology.
8. Developer docs may use literal paths where required.
9. Privacy docs must be mechanism-first.
10. Keep copy concise, concrete, and non-hype.
11. Use the uploaded latest repo and handoff files as the source of truth.
12. If a behavior is unclear, mark it as a verification item instead of guessing.
