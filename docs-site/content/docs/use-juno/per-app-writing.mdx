# Per-app Writing

The same spoken input can produce different output depending on the active app.

> *"ask Avery to review the Q3 onboarding notes before Friday"*

| App | What Juno writes |
| --- | --- |
| **Mail** (Formal email) | Avery, could you review the Q3 onboarding notes before Friday? I would like to identify any issues before release. |
| **Slack** (Casual chat) | avery can you review q3 onboarding before friday? |
| **Apple Notes** (Structured notes) | **Q3 onboarding** — Avery review before Friday. |

Per-app writing assigns style, context, and privacy behavior to an app.

## How to configure

1. Open **Juno → Per-app writing** (sidebar)
2. Click the app picker at the top — choose from running apps, or add a bundle ID manually
3. Set the **writing style** for that app
4. Override any of the four **Privacy here** toggles
5. Open **Advanced** for tone hints, window-title hints, and listening hints

Changes apply to the next session in that app. Settings are stored per bundle ID.

## What you can control

| Control | Effect |
| --- | --- |
| **Writing style** | The style that activates automatically when this app is focused. Overrides your global default. |
| **Use context** | Whether Juno can read selected text and clipboard hints inside this app. Tri-state: follow global, force on, force off. |
| **Learn corrections** | Whether edits made in this app are folded into Dictionary & Memory. Tri-state. |
| **Save history** | Whether dictations in this app appear in History. Tri-state. |
| **Keep recordings** | Whether audio is retained for replay or reprocessing in this app. Tri-state. |

Per-app overrides can only make Juno stricter than your global setting, not looser. If global history is off, setting an app to "history on" has no effect. Secure-field protection always wins regardless.

## Advanced

The Advanced disclosure exposes three text hints that improve writing quality for that specific app:

| Hint | What it does |
| --- | --- |
| **Include window title when listening** | Toggle — when on, the window title is added to context. Useful for apps where the title names the document or channel ("#general — Slack"). |
| **Listening hint** | A free-form text note Juno applies to dictation in this app. Example: "Speak in second person for these messages." |
| **Tone hint** | A free-form tone note. Example: "Casual but precise; avoid corporate phrasing." |

These hints are app-local; they do not affect dictation in any other app.

## Recommended setups

| App type | Style | Privacy posture |
| --- | --- | --- |
| **Notes, drafts, journals** | Structured notes or Default | Context on, history on, recordings to taste |
| **Mail, Outlook** | Formal email | Context on, learning on, history to comfort |
| **Slack, iMessage, Discord** | Casual chat | Context on, learning on |
| **Cursor, VS Code, JetBrains** | Verbatim or a custom code-comment style | Context off when source material is sensitive; recordings off |
| **Terminals (iTerm2, Terminal, Warp)** | Verbatim | Context off, learning off |
| **Remote desktop clients (Jump, Royal TSX, Parallels)** | Any; insertion normally falls back to Copy Ready | Context off, recordings off |
| **Password managers (1Password, Bitwarden)** | Not needed | Already secured by the secure-field rule |
| **Legal, medical, client work** | Formal email or Default | History off, recordings off, learning off |

## When to use per-app settings

- **Wrong output format** — set a more appropriate default style for the app.
- **Stricter privacy needed** — disable history, recordings, context, or correction learning for that app.
- **Custom phrasing needed** — use Advanced → Listening hint and Tone hint for app-specific terminology or tone.

Use Per-app writing for one-app exceptions; do not change global settings to fix a single app.

For the deeper privacy model and how each context source changes output, see [Smart Context](/docs/privacy-and-data/smart-context) and [Privacy and Data Overview](/docs/privacy-and-data/overview).
