# Release Process

Each public Juno release is prepared as a complete app and documentation update. A release includes the signed macOS app, local model payload, updated docs, current screenshots, support flow, and published release notes.

## What is verified before release

- Clean install on a fresh macOS user profile
- Permission setup, first dictation, insertion, quit, and relaunch
- Local engine startup without a source checkout or developer tools
- Developer ID signing, hardened runtime, notarization, and stapling
- Microphone, Accessibility, Speech Recognition, and Input Monitoring flows
- Secure-field blocking for passwords and other protected inputs
- History, recording retention, export, and deletion behavior
- Copy Ready fallback in unsupported or unsafe insertion targets
- Support bundle generation and privacy review
- Documentation build, link check, screenshot review, and final copy review

## Changelog policy

Release notes are published only after the app build and documentation pass final review. Each changelog entry should describe user-visible changes, compatibility notes, and any required setup steps.

## Screenshot policy

Release screenshots must come from the current product. Do not publish private user data, generated product mockups, or screenshots from older builds.
