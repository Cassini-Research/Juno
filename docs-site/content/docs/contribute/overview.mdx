# Contribute to Juno

Juno contributions should preserve the core product contract: local-first voice writing, truthful HUD states, safe insertion, copy-ready recovery, privacy-controlled context, local history/recordings, and explicit user control over learning and retention.

## Good contribution areas

High-value work usually falls into one of these areas: Mac shell reliability, local engine stability, speech quality, latency, safe insertion, privacy policy enforcement, dictionary/memory controls, tests, QA fixtures, packaging, signing, documentation, and high-signal examples.

## Before opening a pull request

Read the product reference files, run the test suite, and verify that your change does not weaken secure-field suppression, local token auth, retention behavior, or copy-ready fallback.

```bash
./scripts/run_tests_v2.sh
```

For app-level changes, run manual GUI QA on a real Mac. Do not mark a Mac behavior complete based only on headless tests.

## Contribution style

Prefer small, auditable changes. Include source paths, tests, before/after behavior, and any manual verification performed. Avoid broad rewrites that mix UI, engine, model, storage, and documentation changes unless the issue explicitly requires it.
