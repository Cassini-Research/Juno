# Debugging

Start from the layer that owns the failure.

## First checks

Run:

```bash
./scripts/doctor_v2.sh
./scripts/run_tests_v2.sh
```

Then inspect runtime health, setup status, engine compatibility, and app permissions.

## Engine unavailable or incompatible

Check whether a stale local service is running on the expected endpoint. The app should verify protocol version and runtime role before attaching. If compatibility fails, restart the managed engine path and confirm the compatibility endpoint returns the expected production role and protocol version.

## Microphone issues

Differentiate missing permission from no frames. The HUD should show a microphone/setup state until real frames are observed. No frames within the watchdog window should become a user-actionable microphone error.

## Insertion issues

Check Accessibility permission, active app detection, secure-field policy, selected-text state, and paste helper output. If final text exists and insertion was unsafe or blocked, the correct recovery is copy-ready output.

## History and recordings

Check product history SQLite path, audio root, retention settings, linked recording IDs, and cleanup behavior. A history entry can remain after its linked recording expires or is deleted.

## Memory and corrections

Check whether the surface suppresses learning. Secure fields and per-app overrides can block correction learning even when global learning is on.
