# Developer Mode

Developer mode exists to make local hacking and tests faster. It must not leak into default product copy or normal user flows.

## Key switches

| Switch | Meaning |
| --- | --- |
| `JUNO_DEV_NO_AUTH=1` | Disables local token enforcement for development. Do not use in packaged user flows. |
| `JUNO_APP_SUPPORT_DIR=/path` | Overrides the support root for tests and isolated local runs. |
| `JUNO_PRODUCT_HISTORY_DIR=/path` | Overrides product history storage. |
| `JUNO_PRODUCT_AUDIO_DIR=/path` | Overrides retained audio storage. |
| `JUNO_SKIP_MLX_PREFLIGHT=1` | Skips MLX/Metal preflight checks. Use only when intentionally bypassing that guard. |

## User-facing boundary

Default onboarding and user docs should say **local voice engine**, **history**, **recordings**, **settings**, and **support bundle**. Developer implementation terms belong in developer pages.

## Debug surfaces

Developer-mode debug surfaces include runtime artifacts, latency logs, model route inspection, route swapping, and generated summaries. Treat them as engineering tools, not product UI.
