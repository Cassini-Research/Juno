## Module map

| Module | Path | What it does |
| --- | --- | --- |
| Audio capture | `juno_v2/audio/` | Receives PCM frames from the shell; resampling, normalization |
| Voice activity detection | `juno_v2/vad/` | Decides when speech starts and ends |
| Streaming ASR | `juno_v2/asr/` | Speech → text, with both partial and final results |
| Writing engine | `juno_v2/transforms/` | Polishes the raw transcript: punctuation, casing, removed disfluencies |
| Modes | `juno_v2/modes/` | The six built-in styles (verbatim, casual_chat, formal_email, structured_notes, explicit_rewrite, command_mode) plus user custom modes |
| Action grammar | `juno_v2/actions/grammar.py` | Detects the "Hey Juno / Juno" action prefix and parses the action verb |
| Memory | `juno_v2/memory/` | Dictionary, snippets, replacements, style entries — applied at output time |
| Personalization | `juno_v2/personalization/` | Folds confirmed corrections back into memory |
| Bridge | `juno_v2/engine/bridge.py` | Unix socket protocol the shell talks to |

## Two passes per session

The engine runs two transcription passes per dictation:

1. **Fast preview** during the session — used for the live captions in the HUD and pause-driven partial commits. Lower quality, sub-second latency.
2. **Final dictation** at the end — when the user finishes the session, the engine runs the full audio through a higher-quality model and produces the final result.

The active mode determines whether the final result is also routed through the writing engine. Verbatim, Default, and Casual chat take the speech result directly. Formal email, Structured notes, Polished rewrite, and Commands route through the writing engine for a stylistic rewrite.

## Action grammar

The action-prefix regex lives at `juno_v2/actions/grammar.py:33`:

```
_WAKE_RE = r"^\s*(?:hey[\s,.!?:;\-—]+)?juno\b…"
```

It is anchored to start-of-transcript and only runs once a transcript exists. If a transcript begins with "Hey Juno" or just "Juno," and the rest is a recognizable action verb (remind me / take a note / set an alarm / wake me up / set a timer / ping me / remember to / …), the engine routes the request to the action pipeline and the literal prefix text is suppressed from insertion. Otherwise, the transcript becomes ordinary dictated text.

## Models

Three model categories ship. Each shows installed / installing / ready / failed in Settings → Models, with a **Repair** action that re-fetches weights. Models live under `~/Library/Application Support/com.juno.shell/models/`.

| Category | Used by | Status surface |
| --- | --- | --- |
| Fast preview | Live captions, pause partials | Settings → Models → Fast preview |
| Final dictation | Final session result | Settings → Models → Final dictation |
| Writing engine | Modes that need rewriting (Formal email, Structured notes, Polished rewrite, Commands) | Settings → Models → Writing engine |

### Shipping Apple Silicon configuration

The actual model identifiers Juno ships against today on Apple Silicon:

| Lane | Model identifier | Backend |
| --- | --- | --- |
| Fast preview | `mlx-community/whisper-large-v3-turbo` | MLX (`juno_v2/asr/`, streaming-decoded) |
| Final dictation | `mlx-community/whisper-large-v3-turbo` | MLX (same weights, full-pass decode) |
| Writing engine | `mlx-community/Qwen3-4B-Instruct-2507-4bit` | MLX LM (quantized 4-bit, on-demand load/unload) |

The two ASR lanes share weights to keep cold install small. The writing engine loads on demand and unloads after each transform, so it does not remain in memory between rewrites. The underlying engine also supports `parakeet_streaming` and a `faster_whisper` CPU fallback, but the consumer picker does not expose them.

Configuration source: `juno_v2/demo/config.py`. Per `juno_v2/runtime/mlx_lock.py`, MLX threads are serialized so the streaming preview and the final pass do not contend for Metal allocation.

### Hallucination and repetition guards

Whisper-family models can produce implausible output on uncertain audio. Juno applies two on-device post-filters between the final ASR pass and the writing engine:

| Guard | Module | What it catches |
| --- | --- | --- |
| Hallucination guard | `juno_v2/memory/hallucination.py` | CJK glyph repetition on silence; word-ratio anomalies (more words/sec than human speech can produce) |
| Anti-repetition post-filter | `juno_v2/memory/repetition.py` | Periodic tail repetitions when words-per-second exceeds a natural-speech threshold |

Both are deterministic, fast, and run before the writer sees the output. They were added after observing real `whisper-large-v3-turbo` failures on background noise and silent audio. Test fixtures are in `tests_v3/test_actions_*` and `juno_v2/transcript/contracts.py` carries the contract.

## What the engine does not have

- No network activity beyond model file downloads (read-only fetches from a public model repository)
- No telemetry, usage pings, or persistent off-device connection
- No cloud LLM fallback — even if a local model fails, there is no remote inference path
- No opt-in to share user content for training

## When the engine is not ready

The shell detects engine state through the bridge. If the engine is not responding or has not finished warming, Home shows a Setup/Connecting/Offline state instead of Ready. Pressing the shortcut while the engine is not ready opens Home rather than starting a session.

See [Voice Engine Not Connected](/docs/troubleshooting/voice-engine-not-connected) for the user-facing recovery path.
