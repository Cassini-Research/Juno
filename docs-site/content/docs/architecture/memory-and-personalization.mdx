# Memory and Personalization

Memory applies local vocabulary, replacements, snippets, and learned corrections.

Everything is local. Memory entries live in `~/Library/Application Support/com.juno.shell/Memory/` and are never uploaded.

## Four memory categories

| Category | What it does | Example |
| --- | --- | --- |
| **Vocabulary** | Spelling and capitalization of names, products, technical terms | "Polkadot" stays capitalized; "Juno" never transcribes as "Uno" or "Junior" |
| **Snippets** | Phrases that expand from a short trigger | Trigger `my calendar link` expands to your scheduling URL |
| **Replacements** | One word/phrase always becomes another | "kuberneties" → "Kubernetes" |
| **Style entries** | Preferences applied to writing | "Use Oxford commas," "American spelling," "no exclamation marks in formal mode" |

Each lives under `juno_v2/memory/` and is applied during the writing-engine pass, after raw transcription.

## Snippet scopes

Snippets can be scoped to where they're allowed to expand:

| Scope | Expands in |
| --- | --- |
| Global | Everywhere |
| Messaging | Slack, iMessage, Discord, similar chat apps |
| Email | Mail, Outlook |
| Docs | Notes, Pages, Word, Google Docs, Notion, Obsidian |
| Code | Cursor, VS Code, JetBrains, Xcode |

A code-scoped snippet expanding "TODO comment" into a structured block is useful in Cursor; you don't want it firing in a Slack message.

## The correction-learning loop

When the user edits a dictation result (in History → Re-run, or by manually correcting freshly-inserted text), `juno_v2/personalization/` observes the edit and decides whether it's a candidate for memory:

1. **Capture the edit.** The original transcript and the user's edited version are diffed.
2. **Filter by confidence.** Trivial single-character typos and one-off changes don't become memory. Repeated patterns (the same name corrected three times, the same phrase replaced consistently) do.
3. **Confirm with the user before learning anything destructive.** Vocabulary additions can be silent. Replacements that would change writing across all future sessions get a confirmation prompt.
4. **Fold into the right category.** A consistent capitalization fix becomes a Vocabulary entry; a phrase-to-phrase swap becomes a Replacement.

Personalization respects all the same hard gates as the rest of the system: it's off in secure fields, off when learning is disabled globally, off when per-app learning is disabled for the current app.

## What memory does NOT do

- It does not train any model. Memory is rule-based application + dictionary lookup, not a neural fine-tune.
- It learns from edits made anywhere — including edits you type in the destination app after Juno inserted text. The `JunoTextMonitor` helper observes selected-text and recently-inserted-text changes via the Accessibility API, then `juno_v2/personalization/` diffs Juno's output against your edit and stores observed→corrected pairs.
- It does not sync across devices. Each Mac has its own memory.
- It does not remember anything from a session that ran in a secure field.

## Inspecting and editing memory

Open the **Dictionary & Memory** page in the Juno sidebar. Every memory entry is visible there with its category, source ("seed promotion" / "user added" / "learned from correction"), and an Edit / Delete control. Every applied entry is visible on this page.

For the user-facing guide, see [Dictionary and Memory](/docs/use-juno/dictionary-and-memory).
